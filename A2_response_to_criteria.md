### Core - Statelessness

- **What data is stored within your application that is not stored in cloud data services?:** Temporary transcoding and image processing files generated by ffmpeg/sharp.
- **Why is this data not considered persistent state?:** They can be recreated from the original S3 file at any time.
- **How does your application ensure data consistency if the app suddenly stops?:** All persistent state (videos, screenshots, tasks) is stored in DynamoDB and S3. Tasks are resumed or retried from DynamoDB records.
- **Relevant files:**
    - src/controllers/videoController.js
    - src/controllers/screenshotController.js
    - src/utils/ffmpeg.js
    - src/utils/sharp.js

### Graceful handling of persistent connections

- **Type of persistent connection and use:** Server-Sent Events (SSE) used to push task progress updates (e.g., transcoding/image processing status).
- **Method for handling lost connections:** Client automatically reconnects if the connection drops; server ends stream when task completes or fails.
- **Relevant files:**
    - src/routes/tasks.js (SSE endpoint and streaming logic)
    - src/utils/dynamo.js (getTaskStatus)
